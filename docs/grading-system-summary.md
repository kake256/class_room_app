# 講義課題 自動採点システム 概要(2026-07-20時点)

機械学習講義のClassroom課題を、ローカルLLMで半自動採点し成績簿へ下書き入力するシステム。
TAの採点作業を「全答案の採点」から「システムが迷った1〜2割の確認」に置き換えることを目的とする。

## 1. 何ができるか

- Google Classroomから提出物(PDF / Googleドキュメント / Word)を自動取得
- 研究室GPUサーバー上のローカルVLM(視覚言語モデル)で答案画像を採点
- 採点結果をClassroom成績簿へ**下書き**として自動入力し、確定できる答案は返却まで自動化
- 学生データは外部サービスへ一切送信しない(取得・採点・保存すべて研究室内で完結)

## 2. 採点の仕組み(なぜ信頼できるか)

単一のLLM出力をそのまま使わず、多段の相互チェックで確信度を測る:

1. **一次採点**(Qwen2.5-VL-7B)を2回 — 甘め・高再現率の粗選別
2. **審判再採点**(Qwen3-VL-8B)を2回 — 厳密な絶対評価
3. **ペアワイズ比較** — 満点候補を基準答案と直接比較
4. 各段階の一致・不一致から答案を3層に分類:

| 層 | 意味 | 扱い |
|---|---|---|
| 自動確定 | 全段階で評価が一致 | 入力+返却まで自動(人間は見ない) |
| フラグ付き | どこかで満点評価が出たが最終2点以下 | 下書きのみ入力・返却保留(任意で抜き取り確認) |
| 要確認 | 判定不一致・白紙疑い・満点候補 | 人間が判断してから確定 |

**設計思想: 「間違えない」ではなく「迷ったら必ず人間に回す」。**
誤った点数が人間の目に触れずに学生へ返ることを構造的に防ぐ。

## 3. ルーブリック(採点基準)の設計

- 課題タイプ別テンプレート: 感想文 / 実験レポート / 調査 / 観察
- さらに課題固有の設問に合わせた**専用基準**を定義可能
  (例: 距離計算課題は「テスト点の識別結果」「距離尺度の比較考察」を観点化)
- 採点姿勢をstrict(厳密)/lenient(甘め・感想文向け)で切り替え
- 満点の総数は過去の採点実績に合わせて較正(上限は提出数の3割を目安)し、
  学期を通じた成績分布の一貫性を保つ

## 4. 精度実績(過去課題9件・人間の確定点との照合)

| 課題 | ±1点以内一致 | 平均差(システム−人間) |
|---|---:|---:|
| AdaBoost | 97% | +0.15 |
| Random Forest | 99% | +0.16 |
| 距離計算 | 94% | +0.21 |
| k-NN | 99% | +0.06 |
| SVM | 96% | -0.10 |
| 応用調査(5点満点) | 97% | -0.03 |
| 特別講義感想(100点満点) | 100% | -0.16 |
| 講義感想 | 90% | -0.25 |
| AI感想文 | 94% | -0.24 |

- **全課題で平均差±0.25点以内**(3点満点)。課題タイプによらず一貫
- **満点答案の取り逃がしゼロ**: 満点の可能性が出た答案は必ず下書き止まりで残り、
  人間が確認できる(自動で低い点のまま返却されることはない)
- 人間が満点を付けた答案118件の検証では96%以上が正しく満点評価または人間確認行き

## 5. TAの作業量(実測)

- 要確認は提出68〜70人中**1〜2割**(8〜16人程度)
- 内訳は「満点の最終承認」と「白紙・無関係提出の確認」が大半で、判断の重い中間帯は
  ほぼ自動確定される
- 100点満点課題も自動でスケール換算して扱える

## 6. 関連講義への展開

- 課題とルーブリックの対応は設定ファイル1行で追加
- 新しい課題タイプは「実際の設問+答案数枚を確認して観点を定義→過去課題で検証」の
  手順が確立済み(距離計算課題では平均差-0.94→+0.21まで改善した実績)

## 7. 現在の状態と今後

- 完成度: 主要機能は動作済み、過去課題での精度検証完了。現在は今学期課題での
  実運用検証段階
- 今後: 今学期課題(好きな手法・MLP)の返却後の答え合わせ、モデル切り替えの自動化、
  Web UIからの確認作業の効率化
